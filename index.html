Dołączasz do zespołu backendu Lumio TV. Nasze telewizory stoją w milionach domów i każdego dnia pytają serwer o aktualizacje firmware'u i o katalog aplikacji. Ty odpowiadasz za ten serwer. Na rozgrzewkę zbudujesz aplikację Pogoda na telewizor, trzy razy i za każdym razem inną metodą.     Przygotowanie

    Cel: repozytorium pogoda-start działa, agent widzi skille i potrafi uruchomić testy, a potwierdza, że środowisko jest gotowe.

    Zasady pracy w tych modułach

    • Każda wersja na osobnej gałęzi od start. Dzięki temu na końcu porównasz wszystkie trzy.
    • Commit przed przejściem do kolejnego zadania. Inaczej niezacommitowane zmiany przejdą na następną gałąź.
    • Nowa sesja agenta na każde zadanie. W porównaniu ma się liczyć metoda pracy, nie to, co agent pamięta z poprzedniej wersji.
    • Notuj na bieżąco. Poprawki i zaskoczenia zapisuj od razu, po fakcie szybko się zacierają.

    Nie masz Pythona? Instalacja przenośnej wersji na Windowsie

    Przenośny Python nie wymaga instalatora ani uprawnień administratora. Rozpakowujesz go do folderu w repozytorium i od razu działa. Na macOS i Linuksie Python zwykle jest w systemie; jeśli go nie ma, napisz do trenera.

    1. Pobierz Python 3.15.2, Windows embeddable package (64-bit). Na laptopie z procesorem ARM (np. Snapdragon) wybierz wersję ARM64 ze strony pobierania Pythona dla Windows.
    2. Odblokuj pobrany plik: prawy klik na ZIP, Właściwości, zaznacz „Odblokuj”, OK. Jeśli tej opcji nie ma, przejdź dalej.
    3. Rozpakuj zawartość do folderu python w katalogu repozytorium, tak żeby plik leżał tutaj: <repozytorium>\python\python.exe. Git ten folder pomija.
    4. Uruchom w agencie . Skill znajdzie rozpakowanego Pythona, także gdy wylądował w dodatkowym podfolderze, i zaproponuje przeniesienie go na miejsce oraz konfigurację. Każdą zmianę zatwierdzasz. Jeśli raport pokaże „Python: ✅”, pozostałe kroki możesz pominąć.
    5. Konfiguracja ręczna, jeśli wolisz zrobić to sam: otwórz w Notatniku plik python\python315._pth, dopisz na końcu linię z dwiema kropkami i zapisz. Dzięki temu Python widzi kod repozytorium. Plik ma wyglądać tak:

    Walidator paczki firmware'u

    Cel: napisać walidator metodą TDD. Najpierw czerwony test, potem minimalny kod, na końcu porządki przy zielonych testach.

    Zanim telewizor zainstaluje paczkę, serwer sprawdza, czy jest poprawna. Specyfikacja formatu jest poniżej, a wektory testowe (wejście w hex i oczekiwany wynik) są w fixtures/firmware_vectors.json.

    Specyfikacja formatu paczki
    Format LMFW: paczka = nagłówek (16 bajtów) + payload.

Nagłówek:
  bajty 0-3    magiczne bajty, ASCII "LMFW" (wielkie litery)
  bajt  4      wersja nagłówka, obecnie 1
  bajty 5-7    wersja firmware: major, minor, patch (po 1 bajcie)
  bajty 8-11   rozmiar payloadu w bajtach, uint32 big-endian
  bajty 12-15  CRC32 payloadu, uint32 big-endian

Maksymalny rozmiar payloadu: 16 MiB (16 777 216 bajtów).

Wynik walidacji:
  poprawna paczka -> valid: true,
                     version: "major.minor.patch",
                     payload_size: rozmiar payloadu
  błędna paczka   -> valid: false, error: jeden kod błędu

Kody błędów, w kolejności sprawdzania
(zwracany jest pierwszy napotkany):
  1. TRUNCATED           mniej niż 16 bajtów
  2. BAD_MAGIC           magiczne bajty inne niż "LMFW"
  3. UNSUPPORTED_HEADER  wersja nagłówka inna niż 1
  4. TOO_LARGE           zadeklarowany rozmiar powyżej 16 MiB
  5. EMPTY_PAYLOAD       zadeklarowany rozmiar równy 0
  6. SIZE_MISMATCH       faktyczna długość payloadu inna
                         niż zadeklarowana
  7. BAD_CRC             CRC32 payloadu inne niż w nagłówku

    Do tej pory agent znał tylko pliki repozytorium. Teraz dostanie narzędzia: najpierw podłączysz gotowy serwer MCP i sprawdzisz, komu ufasz, a potem zbudujesz własny. Serwery są w katalogu mcp_server/, opis plików jest w mcp_server/README.md.

    5a

    Gotowy serwer MCP

    Cel: agent korzysta z danych Lumio przez serwer MCP, a Ty widzisz, które narzędzia wywołuje i z jakimi argumentami. Rozróżniasz narzędzia (tools), zasoby (resources) i prompty.

    Zespół backendu ma serwer MCP Lumio Ops (mcp_server/lumio_ops.py): rejestr urządzeń, wydania firmware'u i bieżące reguły OTA. Support chce pytać o telewizory agenta, zamiast przeglądać pliki JSON.

    Kroki

    Jak podłączyć serwer: Claude Code

    Utwórz w katalogu głównym repozytorium plik .mcp.json. W command wpisz Pythona ze środowiska .venv, bo tylko on ma SDK. Poniżej wersja dla Windowsa. Na macOS i Linuksie końcówka ścieżki to /.venv/bin/python. Bez .venv wpisz polecenie, które działa u Ciebie: python, python3 albo py z pierwszym argumentem "-3".

  "mcpServers": {
    "lumio": {

    Bez SDK: MCP na czystym stdlib

    Gdy nie da się zainstalować pakietu mcp, serwery z mcp_server/ używają mcp_server/mcp_lite.py. To około 250 linii na bibliotece standardowej, z tym samym API co oficjalne SDK dla tego, czego używamy na szkoleniu. W swoim serwerze zmieniasz tylko importy:

    try:
    from mcp.server.mcpserver import MCPServer
    from mcp.server.mcpserver.exceptions import ToolError
    from mcp.types import ToolAnnotations
    from pydantic import Field
except ImportError:
    from mcp_lite import MCPServer, ToolError, ToolAnnotations, Field

    Pod spodem MCP przez stdio to JSON-RPC: agent uruchamia serwer jako proces, pisze do jego wejścia po jednej wiadomości JSON w linii (initialize, tools/list, tools/call) i czyta odpowiedzi z wyjścia. Dlatego serwer nie może niczego wypisywać na stdout, logi kieruje na stderr. Przykładową wymianę wiadomości i listę ograniczeń mcp_lite znajdziesz w mcp_server/README.md.

    • Jakie gotowe serwery MCP przydałyby się Twojemu zespołowi: repozytorium kodu, tracker zadań, baza danych, dokumentacja?

    Jak ograniczyć uprawnienia w kliencie

    Claude Code. Reguły dla siebie wpisz w .claude/settings.local.json (git go pomija). Kolejność sprawdzania: najpierw deny, potem ask, na końcu allow. Nazwa reguły to mcp__<serwer>__<narzędzie>, a mcp__lumio oznacza wszystkie narzędzia serwera.

    .claude/settings.local.json
    {
  "permissions": {
    "allow": [
      "mcp__lumio__list_devices",
      "mcp__lumio__get_device",
      "mcp__lumio__pending_update"
    ],
    "ask": ["mcp__lumio__set_device_firmware"],
    "deny": ["mcp__lumio__reset_devices"]
  }
}

    W chmurze plik lokalny nie przetrwa sesji. Dopisz sekcję permissions do .claude/settings.json w swoim forku na GitHubie i zacznij nową sesję.

    Cline. W ustawieniach MCP wpisz do autoApprove tylko narzędzia do odczytu: ["list_devices", "get_device", "pending_update"]. Pozostałe Cline wykona dopiero po Twojej zgodzie. Cline nie ma listy narzędzi zablokowanych: jeśli narzędzie nie może się wykonać nigdy, wyłącz je po stronie serwera.

    Szkielet serwera MCP 
    """Katalog: which apps a TV shows, and why."""

import sys
from pathlib import Path
from typing import Annotated

sys.path.insert(0, str(Path(__file__).resolve().parent.parent))

try:
    from mcp.server.mcpserver import MCPServer
    from mcp.server.mcpserver.exceptions import ToolError
    from pydantic import Field
except ImportError:
    from mcp_lite import MCPServer, ToolError, Field

from backend.catalog import get_apps_for_device
from backend.registry import DeviceNotFound, DeviceRegistry
from backend.storage import JsonStore

store = JsonStore()
registry = DeviceRegistry(store)
mcp = MCPServer("katalog")


@mcp.tool()
def list_apps_for_device(
    device_id: Annotated[str, Field(description="Identyfikator telewizora, np. TV-002.")],
):
    """Aplikacje widoczne na ekranie głównym telewizora, w kolejności z ekranu.

    Użyj, gdy pytanie brzmi „co widzi telewizor X”. Zwraca id, nazwę i wersję każdej aplikacji.
    """
    try:
        device = registry.get(device_id)
    except DeviceNotFound:
        raise ToolError("Nie ma urządzenia %s. Listę urządzeń zwraca list_devices z serwera lumio." % device_id)
    return {"device_id": device_id, "apps": get_apps_for_device(store, device)}


if __name__ == "__main__":
    mcp.run(transport="stdio")
    • Rejestracja: dekorator @mcp.tool(). Nazwa narzędzia to nazwa funkcji, opis to docstring, schemat parametrów powstaje z adnotacji typów.
    • Opis parametru: Annotated[typ, Field(description=...)]. Parametr z wartością domyślną jest opcjonalny.
    • Wynik: słownik lub lista trafia do agenta jako JSON, napis jako tekst.
    • Błąd dla agenta: ToolError z komunikatem, co zrobić dalej. Inne wyjątki agent zobaczy tylko jako „Error executing tool…”.
    • Nigdy print. Standardowe wyjście należy do protokołu. Logi pisz na sys.stderr.
    Po zadaniu: do przemyślenia
    • Co zrobił agent z narzędziem get_data? Które słowo w Twoim opisie najbardziej pomagało mu wybrać właściwe narzędzie?
    • Czy Twój projekt z pola powyżej przetrwał zderzenie z agentem? Co zmieniłeś po pierwszej rozmowie?
    • Które dane z odpowiedzi narzędzia agent naprawdę wykorzystał, a które tylko zajmowały miejsce?
