    Repo publiczne · GitHub Free ok. 30 minut Windows, macOS, Linux

    Wypchnij na GitHub

    Jeśli sklonowałeś repo od kogoś innego, najpierw odłącz stary adres. Polecenie git remote remove origin zwróci błąd, jeśli nie było żadnego adresu, i to jest w porządku.

    terminal
    $ git add -A
$ git commit -m "Ustaw CODEOWNERS"
$ git remote remove origin
$ gh repo create {repo} --public --source . --remote origin --push
    terminal
    $ git add -A
$ git commit -m "Ustaw CODEOWNERS"
$ git push origin main

    Około kwadransa. Testy A i B nie używają modelu i nic nie kosztują. Test C przechodzi cały łańcuch na prawdziwym błędzie z repozytorium.

    A. Token aplikacji i limit pracy (bez modelu)

    Actionsfactory: dispatchRun workflow

    B. Wyłącznik awaryjny (bez modelu)

    C. Pełny łańcuch na prawdziwym błędzie

    W repo jest celowy błąd: formatCents(-50) zwraca "0.50 PLN" zamiast "-0.50 PLN". Załóż zgłoszenie testowe nr 1: Issues → New issue → Bug i wklej pola po kolei.

    Obserwuj zakładkę Actions i samo zgłoszenie. Cały przebieg trwa zwykle kilka do kilkunastu minut.

    1. formularz
      Zgłoszenie dostaje etykietę
    2. factory: triage
      Zdejmuje needs-triage, dodaje komentarz z odtworzeniem błędu i etykietę
    3. factory: dispatch
      Wolne miejsce w limicie, więc zamienia etykietę na
    4. factory: implement
      Gałąź agent/<nr>-…, nowy test, który najpierw nie przechodzi, poprawka w src/money.ts i szkic PR z „Closes #<nr>”
    5. CI
      check zielony
    6. factory: review
      Komentarz z werdyktem i etykieta
    7. Ty
      Ready for review, przegląd zmian w zakładce Files changed, Squash and merge. Zgłoszenie zamyka się samo.
    Jeśli A, B i C przeszły, konfiguracja jest kompletna: aplikacja, sekrety, zmienne, etykiety, reguły gałęzi i cały łańcuch agentów działają.

    D. Więcej zgłoszeń testowych

    Przykład typu Bug to zgłoszenie nr 1 z testu C. Każde z poniższych sprawdza inną decyzję triażu. Zgłoszenia 3–5 możesz założyć naraz, bo żadne nie trafi do implementacji. Zgłoszenia 2 i 6 przy limicie 1 zakładaj po kolei, albo naraz, żeby sprawdzić limit pracy (test E).

    Puste zgłoszenia są w tym repo wyłączoneŻeby ich użyć, zmień w .github/ISSUE_TEMPLATE/config.yml wartość na blank_issues_enabled: true i wypchnij zmianę przez PR. Puste zgłoszenie nie dostaje etykiety z formularza, więc po utworzeniu dodaj needs-triage sam w panelu Labels po prawej.

    Gdy coś nie działa

    Otwórz nieudany przebieg w zakładce Actions, rozwiń czerwony krok i znajdź pasujący objaw.

    ObjawPrzyczyna i naprawa
    Job ma status SkippedFACTORY_ENABLED nie jest dokładnie true. Zdarza się też, że etykieta była inna niż ta, na którą czeka workflow.
    Błąd w kroku create-github-app-tokenZły FACTORY_APP_ID (np. wpisany Client ID), niepełny klucz .pem albo aplikacja niezainstalowana na tym repo (Install App).
    Resource not accessible by integrationAplikacji brakuje uprawnień. Popraw je w ustawieniach aplikacji, a potem zaakceptuj nowe uprawnienia w instalacji: Settings → Applications → Installed GitHub Apps → Configure.
    Akcja odrzuca bota (non-human actor, bot not allowed)FACTORY_BOT_LOGIN nie zgadza się co do znaku ze slugiem aplikacji z dopiskiem [bot]. Sprawdź adres strony publicznej aplikacji.
    Akcja odrzuca użytkownika (write permissions)Zdarzenie wywołał ktoś bez prawa zapisu w repo. To zamierzone. Przeczytaj zgłoszenie i dodaj etykietę sam.
    Łańcuch staje po triażuDispatch nie ma wolnego miejsca: w podsumowaniu jest free slots: 0. Zamknij stary PR agenta albo zdejmij zawieszone agent:in-progress.
    Błąd przy tworzeniu PR lub zgłoszenia przez botaUstawienie „Collaborators only” blokuje aplikację. Przełącz odpowiednią pozycję w Settings → General → Features na All users.
    Błąd uwierzytelnienia API, brak kredytówSprawdź ANTHROPIC_API_KEY, saldo i limit wydatków w Console.
    Brak checku check przy ustawianiu regułCI nie przeszło jeszcze ani razu. Wypchnij dowolny commit na main i poczekaj na przebieg CI.
    Nie mogę scalić własnego PRW rulesecie zostało zaznaczone Require review from Code Owners albo Require approval of the most recent reviewable push, albo Required approvals jest większe niż 0. Popraw to w fazie 5.
    Rework się nie uruchamiaPR nie ma etykiety agent, pochodzi z forka albo wyczerpał limit 2 prób i dostał ready-for-human.
    Błąd: akcja musi być przypięta do SHAZaznaczona jest opcja Require actions to be pinned to a full-length commit SHA w Settings → Actions → General. Odznacz ją.
    Workflow w ogóle się nie pojawia w ActionsPlik nie trafił na main albo Actions są wyłączone (Settings → Actions → General).

    Nic nie pasuje. Skopiuj log z czerwonego kroku i wklej go w rozmowie.
